## Issues Found

### H1. A clear tells subscribers before it deletes, so a subscriber that rebuilds on that callback keeps the deleted properties
**Severity:** High
**Description:**
- `PropertyStore.clear()` registers its one diff and then deletes. Its
  callbacks are delivered inside `register_diffs` (`actor.py:5886`), and
  with no running event loop `deliver` waits. On Flask, and with
  `with_sync_callbacks`, every subscriber is told before anything is
  deleted.
- A subscriber that owes a rebuild runs it on that callback
  (`callbacks.py:1015-1031`, which assumes "the baseline is read after the
  publisher stored this callback's change"). It reads the publisher's live
  properties, which still hold every name, and settles at the clear's
  sequence.
- The replica then keeps every cleared property, with no later diff to
  correct it. The same holds for a data hook that reads back from the
  publisher.
- This is new with the register-first order. The plan's reason for that
  order ("the other order would lose the notification") is about the
  stored diff, not about when it is sent.
**Location:** `actingweb/interface/property_store.py:257-264`;
`actingweb/actor.py:5886-5893`
**Recommendation:**
- Keep registering (storing and numbering) the diff first, but deliver its
  units after the deletes. For example, `register_diffs(...,
  deliver=False)` returns the units, and `clear()` sends them after its loop.
- Add a test with an owed rebuild at the subscriber.
- This also narrows M3.

### M1. On the authenticated callback path, `headers` and `raw_body` come from the caller's body
**Severity:** Medium (peer-reachable)
**Description:**
- `CallbacksHandler.post` builds the hook's data from the caller's JSON and
  overwrites only `method` and `anonymous` (`callbacks.py:902-904`). The
  anonymous path sets both keys from the request (`:332-333`).
- Any authenticated peer the access table admits to `callbacks` can
  therefore put its own `headers` and `raw_body` into the data a flagged
  hook verifies. Example: a captured genuinely signed body beside fields it
  chose, which a hook that verifies `raw_body` and then reads the parsed
  fields accepts (the demo's `webhook_fields` reads both).
- A shared-secret check still needs the secret.
- `docs/reference/hooks-reference.rst:113-114` says the opposite: "An
  authenticated request carries no ``headers`` or ``raw_body``, so such a
  hook refuses it."
- Reported by codex, the code review and the Phase 2 reader. The security
  review dropped it at confidence 4.
**Location:** `actingweb/handlers/callbacks.py:902-904`
**Recommendation:** set `hook_data["headers"]` and `hook_data["raw_body"]`
from the request on both paths; correct the reference sentence; add a test
in which an authenticated peer sends both keys.

### M2. A target-level write of JSON text tells a resource subscriber its resource was deleted
**Severity:** Medium (a peer with write access)
**Description:**
- The JSON-text guard in `_resource_went` covers subtarget writes only
  (`actor.py:5934`, `if subtarget and isinstance(held, dict) ...`).
- For `POST /properties {"config": "{\"a\": 1}"}` over a `config` that held
  `a`, the function returns `True` (reproduced by the outside voice), and a
  resource subscriber on `config/a` is sent `""` while the publisher still
  serves `a`.
**Location:** `actingweb/actor.py:5917-5946`
**Recommendation:** parse `new[sub["subtarget"]]` with `_parsed_value` at
target level, and return `False` when it holds the resource. Apply the same
parsing where `register_diffs` indexes `jsonblob[subtarget][resource]`, so
the update itself is sent. Add a test.

### M3. A clear deletes a value written while it ran, and the subscribers keep that value
**Severity:** Medium
**Description:**
- `clear()` snapshots the names (`property_store.py:243`), registers diff N,
  then deletes every name (`:264`).
- A `PUT x` that lands in between stores x and diff N+1, and the clear then
  deletes x. The publisher has no x, while every subscriber applied N+1 and
  holds it.
- The 3.15 loop deleted and then registered per key, so the subscribers
  followed the publisher.

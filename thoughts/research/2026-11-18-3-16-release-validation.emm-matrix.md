## How a cell was filled

1. **covered**: a test executes the same library method (or the same implementation, when the test enters it through a route that calls it) and asserts on the result. For trust, subscriptions and diffs it must be an integration test or wire row between two actors created over HTTP on the harness apps, with no backend pin.
2. **partly**: the method the application calls is executed by a qualifying test, but not in the way the application calls it. The reason is always one of: other arguments, executed but not asserted, one of several methods in the row untested, or (outside the three peer areas) one backend only.
3. **GAP**: no qualifying test executes the method. That includes a pass-through whose delegate is tested while the method itself is never called (the cell names the delegate's test), a separate async implementation whose sync twin is tested, and, for the three peer areas, a method whose only tests are on one actor, in-process, mocked or on one backend. The cell always names the nearest test.
4. **mocked** is said where a test replaces the layer under test.
5. Sync versus async: `subscribe_to_peer_async`, `sync_peer_async` and `store_permissions_async` are separate implementations in the library, not wrappers of their sync twins (`actingweb/interface/subscription_manager.py:591`, `:3806`; `actingweb/trust_permissions.py:322`), so a test of the sync twin leaves the async one a GAP. Methods the application runs through `asyncio.to_thread` or `run_in_executor` are sync calls, and a sync test counts.
6. Both backends: the integration suite takes its backend from `DATABASE_BACKEND` and the wire rows have one recording for both (`tests/integration/_wire.py:1029`), so an integration test without `skipif`, `pytest.skip` or a hard-coded `database=` runs on both. Unit tests built on `tests/_adoption_helpers.py::make_config()` (default `database="dynamodb"`, a keyword that wins over the environment, `tests/_adoption_helpers.py:30`) run on DynamoDB whatever the run's backend, even where the module docstring says "both backends"; `tests/conftest.py:124` says the same.
7. Deployment shape: no integration or wire fixture runs an application with `sync_callbacks=True` (section "Fixtures" below). Rows whose behaviour is callback delivery say so.

Wire rows are cited as `<row id>` with their scenario function; all live under `tests/integration/` and are registered in `tests/integration/wire/rows.toml`.

## 2026-11-18, after verification thoughts/verifications/2026-11-17-3-16-pre-rc1-fixes.md

1. **[Verification fix] The empty-answer delete reads the list names strictly** — `list_all_lists(strict=True)` before deleting the replica's list (`actingweb/handlers/callbacks.py`, `tests/test_permission_callback_fetch.py::test_an_empty_answer_with_the_list_names_unreadable_raises`). Why: a read fault answered `[]`, so the list stayed and the value was reported removed; now the fault raises before anything is deleted. The verification's "no 503" was wrong: this sync runs after the permissions are stored and its caller logs a `DbError` by design. AC: none (regression test, red: did not raise). Spec: none.
2. **[Verification fix] `get_permissions_uncached` never answers from the cache** — the bucket read is factored out of `get_permissions` into `_read_permissions`, which the uncached read calls directly and which caches what it read (`actingweb/trust_permissions.py`, `tests/test_permission_cache_bounds.py::test_the_uncached_read_is_never_answered_from_the_cache`). Why: another thread could refill the entry between the pop and the read, so `update_permissions` could merge into a stale override. AC: none (regression test, red: the stale override). Spec: none.
3. **[UX refinement] The retry text only on a refused creator or passphrase** — `WwwHandler.require_authenticated_actor` keys on the Auth's own "Invalid username or password" result instead of any 403 with a Basic header (`actingweb/handlers/www.py`, `tests/test_web_ui_basic_challenge.py::test_a_403_that_is_not_a_wrong_passphrase_gets_no_retry_text`). Why: an actor with no passphrase was told to close the browser, which cannot help. AC: AC-24 added. Spec: `thoughts/specs/web-ui.md` WUI-2 updated, its Untested line removed.

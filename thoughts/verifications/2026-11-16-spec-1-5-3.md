## Issues Found

### B1. A rebuild run by an incoming callback skips the application's data hooks
**Severity:** Medium.
**Who reaches it:** any publisher's ordinary diff callback once a rebuild
is owed and due, for example after a failed resync fetch. No attacker is
needed.

**Description:** `callbacks.py:1043-1048`, when the rebuild succeeds,
returns before the handler runs:

```python
if mgr._rebuild_owed_and_due(peer_id, subscription_id, config):
    rebuilt = mgr.rebuild_subscription(...)
    if rebuilt.success:
        return True
```

So `run_subscription_data_hooks` and the legacy `subscription` hook never
run. `rebuild_subscription` (`subscription_manager.py:2637-2849`) calls
neither of them either. The replica gets the change, but the application's
`subscription_data_hook` never sees that callback, or anything else the
baseline folded in.

This path is new in this branch: the owed rebuild runs on the next
callback. It contradicts the owner decision of 2026-11-07 that the gap
resync runs the data hook. Entry 6 restored that for the poll.

**Location:** `actingweb/handlers/callbacks.py:1043-1048`; the same
question applies to the poll's marker rebuild.

**Recommendation:** after a successful rebuild, run the data hooks once,
either with this callback's data, or with the baseline as
`callback_type="resync"`, as a pushed resync is told. Test that a hook sees
the change when the rebuild runs on a callback.

### B2. A publisher's read fault becomes an empty baseline, and the new sweep wipes the subscriber's replica
**Severity:** Medium.
**Who reaches it:** every subscriber of a publisher whose bulk property
read raises anything other than a `DbError`, during a pushed resync or a
rebuild. No attacker is needed.

**Description:**
- `GET /properties` folds such a fault into an empty listing:
  `actingweb/handlers/properties.py:1245-1247`,
  `except Exception as e: logger.error(...); all_rows = {}`. It answers
  200 `application/json` `{}`. That fold predates the branch.
- The subscriber's baseline check accepts `{}` as a valid baseline
  (`subscription_manager.py:274`).
- The resync sweep is new in this branch. For a whole-target subscription
  it deletes every replica name the baseline lacks
  (`subscription_manager.py:240-245`, `stale |= {name ... if name not in
  carried}`).

So one publisher fault deletes the subscriber's whole replica of that peer,
silently. Names the publisher never writes again do not come back until a
later resync.

**Location:** `actingweb/handlers/properties.py:1245-1247`, together with
`actingweb/interface/subscription_manager.py:240-245`.

**Recommendation:** `listall` answers 500 instead of folding the fault into
`{}`; the baseline then fails and the rebuild stays owed. Test it with a
faulting bulk read. The outside voice also suggests, as an option, that the
sweep refuse an empty whole-target baseline when the replica is not empty.

### Low

New in this run:
- **Resync sends follow redirects.**
  - **Where:** `callback_sender.py:185-187`, `requests.post(...)` with no
    `allow_redirects=False`.
  - **How:** the removed `httpx` resync sender did not follow redirects and
    accepted only 200 or 204. Now a 302 that ends at a 200 page counts as
    delivered, and the missed resync is not recorded (`actor.py:4916-4921`).
  - **Also:** a 307 or 308 re-POSTs the body to a host the subscriber
    chooses. `Authorization` is dropped when the host changes.
- **The delivery budget does not apply on the event-loop path**
  (`callback_sender.py:285`).
  - `send_async` uses the fixed timeouts, up to 30 s.
  - The module docstring does not say the budget covers only the waiting
    path.
- **Own-host serialization holds only within one write on a running loop.**
  A `Semaphore(1)` is created per `deliver()` call (`callback_sender.py:287`).
- **A failing `deliver()` can mask a committed write.**
  - **Where:** `actor.py:5925`, `deliver` inside `finally`.
  - **How:** if `ThreadPoolExecutor.submit` raises (thread exhaustion), the
    request answers 500 after the write, so a retried append is
    duplicated.
- **The web UI renders the passphrase** to any caller a `www` access row
  admits (`www.py:307`).
  - The default row is creator-only, so only an application that grants
    `www` to a peer relationship exposes it.
  - `GET /<id>` restricts it to the creator and the trustee.
- **`with_callback_delivery()` cannot turn a budget off once it is set**
  (`interface/app.py:1491`, `if value is not None:`).
- **Hygiene:**
  - `deliver` splits units with `u not in own`, a deep dataclass compare
    (`callback_sender.py:297`).
  - A new pool is built per write.
  - `record_webhook` has no type hints
    (`tests/integration/test_harness.py:424`).
- **Design note:** a resource deleted with its parent is reported only by
  writers that pass `previous=`. `NotifyingListProperty`, the `/items`
  paths and attribute writes do not (`actor.py:5630`).

Unverified (the outside voice did not trace these, and neither did this
run):
- a per-request delivery deadline outliving its request through a copied
  context;
- a 404 for an empty `/properties` from a non-ActingWeb publisher leaving a
  rebuild owed;
- the permission callback's timestamp taken before the grant commits
  (`trust_permissions.py:598`, predates the branch).

## 2026-11-25, after verification thoughts/verifications/2026-11-25-attribute-compare-and-delete.md

1. **[Verification fix] A dict whose one key is a DynamoDB type name is data**: conditions and update actions now pass JSON text through `_serialised` (`db/dynamodb/attribute.py`), and so do `rename_creator`'s `equals` and marker conditions (`db/dynamodb/actor.py`). Why: PynamoDB took `{"S": "x"}` as already serialised. A compare never matched or faulted, and `conditional_update_attr` wrote an unreadable row that failed `delete_bucket` (this predates rc3). Root cause: `pynamodb/expressions/operand.py:201`. AC: AC-32 added. Spec: delta amended.
2. **[Decision changed] The replica deletes a key whose new value it cannot store**: `_refused_unserialisable` deletes the scalar or list before answering `refused` (`remote_storage.py`). Why: skipping left the peer's previous value served as current, and a property stored before the refusal holding `NaN` refused every later resource write. Owner, 2026-11-25: fail closed, as AC-31 does. AC: AC-33 to AC-35 added (AC-34 was already green, kept as a guard). Spec: delta amended.
3. **[Verification fix] An int and a float compare as jsonb's numeric does**: `json_values_equal` compares an int against a float as the decimals their JSON text names (`db/dynamodb/attribute.py`). Why: Python's `==` compares the float's binary value, so `10**30` against `1e30` and `2**70` against `float(2**70)` gave the opposite of PostgreSQL's answer. AC: AC-36 added. Spec: delta amended.
4. **[Verification fix] The public method refuses before it sanitises**: `require_json(expected)` runs before `sanitize_json_data` (`attribute.py`). Why: a circular `expected` raised `RecursionError` from the sanitiser instead of `UnserialisableValue`. AC: AC-37 added. Spec: none (already stated).
5. **[Verification fix] The stored-data condition names the row's `name`**: `_stored_data_condition(bucket, name, stored)` (`db/dynamodb/attribute.py`). Why: the null branch could match a row at the key written under another name. Every release's model requires `name`, so library rows always carry it. AC: AC-38 added. Spec: none.
6. **[Verification fix] Docs: the read cost and legacy `NaN` rows**: the read is for an `expected` that is not a string; a sweep that meets a row holding `NaN` catches `UnserialisableValue` and uses `delete_attr`; the migration guide's replica sentence follows entry 2 (`docs/sdk/attributes-buckets.rst`, `CHANGELOG.rst`, `docs/migration/v4.0.rst`). Why: verification issues 5 and 8. AC: none. Spec: none.
7. **[Verification fix] Type hints on three new tests** (`tests/test_conditional_update_attr.py`). Why: the project requires them on all functions. AC: none. Spec: none.

## 2026-11-25, after the outside voice on iterations 1-7

Why: entry 2 deleted the whole property, losing other subscriptions' paths and the peer's valid write with no rebuild to restore them. AC: AC-35 changed, AC-39 added. Spec: delta amended.

Why: a row 3.x to rc3 wrote through an update with a type-named dict made every delete of its bucket or actor raise `DbError`. AC: AC-40 added. Spec: delta amended.
10. **[Verification fix] `_refused_unserialisable` deletes the scalar only, then logs** (`remote_storage.py`). Why: its `delete_list` branch was unreachable (outside voice 5) and could raise a non-`DbError` inside the handler; the log claimed a delete before it ran (6). AC: none. Spec: none.

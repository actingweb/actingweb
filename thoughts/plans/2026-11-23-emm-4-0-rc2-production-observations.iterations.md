## 2026-11-23, after verification thoughts/verifications/2026-11-23-emm-4-0-rc2-production-observations.md

1. **[Decision changed] Strict mode is the backends', not a re-read** — `conditional_update_attr(strict=True)` raises `DbError` from the backend's exception; the wrapper's `_confirm_conditional_update` is gone (`actingweb/attribute.py`, `db/dynamodb/attribute.py`, `db/postgresql/attribute.py`, `db/protocols.py`). Why: the re-read told two writers of the same value that both won, raised a causeless (so "retryable") error for a permanent fault, compared Python values where the backends compare JSON, and missed expired rows (issues 1, 5, 6, 11). AC: AC-27 dropped, AC-28 and AC-29 added, AC-18 reworded. Spec: delta amended.
2. **[New functionality] `ToolError` on the REST `/actions` route** — the hook runner lets it through and the four verbs answer 400 with `{"error": "<message>"}` (`interface/hooks.py`, `handlers/actions.py`, `handlers/async_actions.py`). Why: the same hook serves REST, where it was logged, dropped and followed by the wildcard hook (issue 3). AC: AC-30 added. Spec: delta amended.
3. **[Verification fix] A `ToolError` for a store fault still alarms** — a fault on its `__cause__` or `__context__` is logged at ERROR with the author's text (`handlers/mcp.py`). Why: the guide's own advice turned an outage into a 200 and an INFO line (issue 2). AC: AC-31 added. Spec: delta amended.
4. **[Verification fix] Only the hook call is a tool failure** — the result is formatted outside the `try`, so a result that cannot be formatted is `Internal error` (`handlers/mcp.py`, `handlers/async_mcp.py`). Why: the model was told to call a tool again that had already run (issue 7). AC: AC-32 added. Spec: delta amended.
5. **[Verification fix] Log lines** — exception and `ToolError` text is logged as its `repr`; a `PermissionError` from a tool is one WARNING without a traceback; `_failure_response` names the prompt or resource (`handlers/mcp.py`, `handlers/async_mcp.py`). Why: a newline in a caller's argument forged a log line, a peer could trigger an ERROR with a traceback per call, and the new line had lost what the old ones named (issues 4, 8). AC: none. Spec: none.
6. **[Verification fix] Documentation** — `classify_fault`'s five-link depth; what a token-cache hit really skips; the resources section's stale error message; the redirect entry's **Behavior change**; the strict example replaced by one whose retry is safe (`actingweb/faults.py`, `actingweb/mcp/token_cache.py`, `docs/`, `CHANGELOG.rst`). Why: issues 9, 10, 12. AC: none. Spec: none.

# Implementation Plan: five fixes 3.16 takes before rc1

**Date:** 2026-11-17
**Branch:** `release/3.16.0-pre-rc1-fixes`, one PR, one phase, two commits (written on `master` at `a416e81`)

No research document: the five items come from the todo sweep of 2026-11-17
(every file in `thoughts/todo/` read and the candidates checked against
`master`). What that check and the evaluation found is under "What Already
Exists" and "Evaluation Notes".

## Overview

Five small defects taken before the release candidate: a permission change
that other workers never see, a client registration that hands out
credentials which can never authorize, two MCP documents that say what the
server does not do, a granted text property that reaches a replica as `{}`,
and a Flask web UI that cannot be signed in to from a browser without an
OAuth provider. They land before
[`3-16-release-validation`](2026-11-15-3-16-release-validation.md), which
judges the release with them in it and carries the `rc1` bump.

## Implementation Order

Plan 5c of the 3.16 plans; the order and the gates are in
[`thoughts/todo/INDEX.md`](../todo/INDEX.md), "Planned for 3.16". **This
plan** needs nothing from the others beyond `master` as it is. Gate 2 (Emm's
suite on this branch before the PR) and gate 3 (a recording shown
byte-identical before it is re-recorded) apply. It re-records two wire rows,
which is why it has two commits: `verify_groups.py` refuses a commit that
makes its own phase an owner of a row it re-records.

## Decisions Made

- **The trust permission cache expires an entry after 300 seconds, a cached
  "no override" included** (owner, 2026-11-17) - the window
  `docs/reference/security.rst` already states for MCP tokens and resolved
  trust entries. A constant, no configuration option.
- **The expiry lives in `BoundedDict`, as an optional `ttl`** - the value
  and the time it was cached are one entry read under one lock, so no writer
  of the cache can forget the stamp and the tests that write raw entries
  keep working. Default `None`: the three peer caches are unchanged.
- **`initialize` advertises `listChanged: false`** for tools, resources and
  prompts (owner, 2026-11-17) - the server never sends the notification.
- **The protected-resource document derives `tools`, `prompts` and
  `resources`** from what the application registered, as `initialize` and
  `/mcp/info` already do, so the three documents agree. Deduced, not asked:
  the owner confirmed the `resources` flag; the outside voice (codex)
  argued for dropping the derivation and the fresh-context reviewer for
  keeping it.
- **Registration writes the trust row first** (owner, 2026-11-17) - trust
  row, then client row, then index. A missing actor, a refused trust or an
  unexpected error then fails with nothing stored and needs no undo. A
  storage fault on the later client writes removes the trust row with one
  targeted delete. This replaces the draft's undo of three rows, which the
  evaluation rated a redesign with new orphan states.
- **A registration on a missing OAuth2 system actor is a 500** - it is a 201
  today, for a client that can never authorize. Follows from the decision
  above.
- **The registration error is `ClientRegistrationError(Exception)`**,
  defined in `actingweb/oauth2_server/client_registry.py`; never a
  `ValueError`, which the server turns into a 400 that echoes its text. The
  500's body is fixed text; the cause is logged only.
- **Flask's check lets a web UI request through when no provider is
  enabled** (owner, 2026-11-17) - the handler then sends the `Basic`
  challenge, as it does on FastAPI today. `/www` routes only: the actor root
  and `/properties*` keep their answer, so no browser shows a credential
  dialog for a script request. No new header code and no second challenge.
- **A granted property's fetch takes the baseline's whole decision** - the
  2xx and not-redirected guards the baseline's caller applies, then
  `_subtarget_value`: text is stored, an empty body or `{}` removes the
  replica's value (what the baseline does with an empty value), and an
  answer that is not the publisher's stores nothing.
- **Changelog categories** - the cache window under `SECURITY` (a narrowed
  or removed grant stayed in force on other workers); `listChanged` and the
  failing registration under `CHANGED` with a **Breaking:** lead; the
  discovery flags, the text property and the Flask web UI under `FIXED`,
  each with its **Behavior change:** sentence.
- **Delta only for the specs** (owner, 2026-11-17) - the merge starts
  `partial` specs from this plan's statements.
- **One phase** (owner, 2026-11-17), in two commits: the first reserves this
  plan in `rows.toml` and takes ownership of the two rows, the second holds
  the fixes and the re-recording.

## What We're NOT Doing

- **Fencing a resync against a diff in progress** - Low in
  `thoughts/verifications/2026-11-16-3-16-pre-validation-fixes.md`, Issue 7
  ("both predate it; the publisher's own timing only"), kept in
  `thoughts/todo/subscription-subscriber-fault-hardening.md`; dropped by the
  owner (2026-11-17).
- **Reaping a client row a storage fault leaves** - the client row is
  written, the index write faults: the row stays, as today
  (`_update_global_index` re-raises). Retention is the DCR todo's design.
- **Routing every internal registration fault to 500** - `oauth2_server.py`
  still answers its catch-all as a 400; only the new error changes. Widening
  it changes an answer no report asked about.
- **A granted text value that parses as JSON** (`[1,2]`, `42`, `true`) - the
  proxy parses any body, so such a value is stored as a list, number or
  boolean, in the baseline too. One rule by content type for both paths is a
  separate change.
- **A `Basic` challenge on the actor root and `/properties*`** - a browser
  would show its credential dialog for script requests (owner, 2026-11-17).
- **A transport condition on the `Basic` challenge** - FastAPI and the
  handler already send it on any scheme; `security.rst` says what it means.
- **Expiry for the trust type registry's cache and the three peer caches** -
  the first holds a trust type's base permissions, the others what a peer
  told this actor; not the finding, and named in `security.rst` so the 300
  seconds is not read as covering them.
- **Cross-process cache invalidation** - the TTL bounds the staleness;
  `mcp-cache-lifecycle-and-revocation.md` section 1 owes the design.
- **MCP 2025-03-26 and batch receive; the hour of access after a client is
  deleted; the other connector-conformance items; the design-owed todos** -
  reviewed 2026-11-17: none breaks a consumer or gets cheaper inside 3.16.
- **The version bump** - `3-16-release-validation` carries it.

## Acceptance Criteria

- **AC-1** (permission cache) — When another process changed a peer's
  permission override more than 300 seconds ago, this process decides that
  peer's access by the changed override.
- **AC-2** (edge: no override cached) — When this process cached "no
  override" more than 300 seconds ago and another process has stored one
  since, this process applies the stored override.
- **AC-3** (edge: within the window; holds today, kept as a guard) — When an
  entry was cached just under 300 seconds ago, a decision uses it and no
  storage read is made.
- **AC-4** (edge: same process; holds today, kept as a guard) — When this
  process stores or deletes an override, its next decision uses the change.
- **AC-5** (registration) — When `POST /oauth/register` cannot create the
  client's trust row because the actor is missing, the trust is refused or
  an unexpected error occurs, the answer is 500 `server_error`.
- **AC-6** (registration, stored state) — After that failure no client row,
  no index row and no trust row exists for the client.
- **AC-7** (edge: storage fault after the trust row) — When writing the
  client row or the index row raises a storage fault, the fault is raised
  (503 at the integration) and the client's trust row is removed.
- **AC-8** (SDK) — When `OAuth2ClientManager.create_client` cannot create
  the trust row, it raises `ClientRegistrationError`.
- **AC-9** (MCP) — For an application with a tool, a resource and a prompt,
  `initialize` answers `listChanged: false` under each of the three.
- **AC-10** (MCP discovery) — `/.well-known/oauth-protected-resource/mcp`
  reports each of `tools`, `prompts` and `resources` true exactly when the
  application registered one.
- **AC-11** (replica) — When a peer grants a property whose value is text
  that is not JSON, the subscriber's replica holds that text after the
  permission callback.
- **AC-12** (edge: not the publisher's answer) — When the fetch after a
  grant is redirected, or answers a 2xx that is neither JSON nor the
  publisher's own text, nothing is stored for that property.
- **AC-13** (web UI, Flask) — When no OAuth provider is configured, a
  request for `/<actor_id>/www` without credentials is answered 401 with a
  `Basic` challenge whose realm is the application's.
- **AC-14** (web UI, FastAPI; holds today, kept as a guard) — The same
  answer on the FastAPI integration.
- **AC-15** (edge: OAuth configured) — When a provider is configured, the
  same request is redirected to sign-in, on both integrations.
- **AC-16** (browser) — In the demo's local QA mode a browser opening
  `/<id>/www` shows its credential prompt.
- **AC-17** (added in plan: the grant fetch takes the baseline's empty rule)
  — When the fetch after a grant answers an empty body or `{}`, the replica
  holds no value for that property afterwards.
- **AC-18** (added in plan: the Flask change is `/www` only) — When no
  provider is configured, an unauthenticated Flask request for
  `/<actor_id>/properties` gets the answer it gets today (401, `Bearer`
  challenge, no `Basic`).
- **AC-19** (added in plan: split from AC-5) — The 500's body carries no
  `client_id`, no `client_secret` and no actor id.
- **AC-20** (added in plan: split from AC-16) — In that browser the creator
  and passphrase sign in, and the walk records what Cancel and a wrong
  passphrase show.
- **AC-21** (added in plan: a provider whose redirect cannot be built) —
  When a provider is configured and the sign-in redirect cannot be built,
  the Flask answer carries no `Basic` challenge.
- **AC-22** (added in implementation: the walk showed the dead end the
  plan anticipated; owner chose a text body, 2026-11-17) — When a wrong
  creator or passphrase is sent to `/<actor_id>/www`, the 403 carries a
  plain-text body saying to close the browser (or open a private window) to
  try again, on both integrations.
- **AC-23** (added in implementation: found by the fast tier) — When no
  provider is configured, a Flask request for `/<actor_id>/www` of an actor
  that does not exist is answered 404, as on FastAPI (it was 401).
- **AC-24** (added in iteration 3) — When a 403 to `/<actor_id>/www`
  with Basic credentials is not a refused creator or passphrase (an actor
  with no passphrase), its body does not say to close the browser, on both
  integrations.

## Spec Delta

No capability has a spec; each file below is new and starts `partial` at
merge, covering only these statements.

### `thoughts/specs/trust-permissions.md` (new spec)

- **ADDED** (Caching) — When a process has cached a peer's permission
  override, or its absence, it uses that for at most 300 seconds before
  reading storage again. (AC-1, AC-2, AC-3)
- **ADDED** (Caching) — When a process itself stores or deletes an override,
  it uses the change at once. (AC-4)
- **DECISION** — The window covers overrides only: a trust type's base
  permissions are cached per process without expiry, and nothing is
  invalidated across processes. There is no option for the window.

### `thoughts/specs/oauth-client-registration.md` (new spec)

- **ADDED** (Registering) — When a registration cannot create the client's
  trust row, it fails (500 `server_error` on `POST /oauth/register`,
  `ClientRegistrationError` from `create_client`), returns no credentials
  and stores nothing. (AC-5, AC-6, AC-8, AC-19)
- **ADDED** (Registering) — When a storage fault interrupts a registration
  after its trust row was written, the trust row is removed; a client row
  already written stays. (AC-7)
- **DECISION** — The trust row is written before the client row, so a client
  that exists always had a trust row created for it.

### `thoughts/specs/mcp-server.md` (new spec)

- **ADDED** (Capabilities) — When `initialize` advertises tools, resources
  or prompts, each says `listChanged: false`: the server sends no
  list-change notification. (AC-9)
- **ADDED** (Discovery) — When the protected-resource document for `/mcp` is
  read, its `tools`, `prompts` and `resources` flags are true exactly for
  what the application registered. (AC-10)

### `thoughts/specs/subscriptions.md` (new spec)

- **ADDED** (Permission callbacks) — When a peer grants a property, the
  subscriber fetches it and applies the baseline's rule for the answer:
  text that is not JSON is stored as text when the publisher itself
  answered with it, an empty body or `{}` leaves no value, and a redirected
  answer or one that is not the publisher's stores nothing. (AC-11, AC-12,
  AC-17)

### `thoughts/specs/web-ui.md` (new spec)

- **ADDED** (Signing in) — When no OAuth provider is configured, an
  unauthenticated request for an actor's web UI is answered 401 with a
  `Basic` challenge, on both integrations; with a provider configured it is
  redirected to sign-in. (AC-13, AC-14, AC-15, AC-16, AC-20, AC-21)
- **DECISION** — Only the web UI routes challenge with `Basic`; the actor
  root and `/properties*` do not. (AC-18)
- **ADDED** (Signing in) — When a wrong creator or passphrase is sent to
  an actor's web UI, the answer is 403 with a text body saying to close the
  browser to try again. (AC-22)
- **ADDED** (Signing in) — When no provider is configured, a web UI request
  for an actor that does not exist is answered 404, on both integrations.
  (AC-23)

### Failure Scenarios

- Cache window - wall-clock time moving backwards keeps an entry alive - a
  monotonic clock; covered by the tests replacing the clock.
- Cache window - every active pair re-reads once per window per process,
  and the trust page pays one read per peer on its first render in a window
  - one consistent point read each, bounded by the cache size; accepted, no
  handling.
- Cache window - a re-read that lands after a concurrent store in the same
  process overwrites it with the older value - bounded by the same 300
  seconds; accepted, no handling (it exists today on a cold entry).
- Cache window - a storage fault on the re-read raises where a cached entry
  answered before - `DbError`, a 503: failing closed is the intent.
- Registration - trust creation runs with no client row yet - the call
  takes only in-memory values and nothing under it reads the registry;
  covered by the integration test and by the wire rows that register
  (`WG14`, `WG16`).
- Registration - the trust row exists and its token entry's write faults -
  the row is removed; covered above.
- Registration - the trust row's removal faults - logged, first fault
  raised; a trust row for a client that does not exist remains, named in
  the log by its peer id, for the operator to remove.
- Discovery - a handler built without `hooks` - the registry functions take
  `None` and answer false; covered by AC-10's test.
- The grant fetch - a login page behind a proxy answers 200 - not stored
  (AC-12).
- The grant fetch - an empty 2xx removes a value the replica held - the
  baseline's rule, stated as AC-17.
- Flask `/www` - a provider is configured but its redirect cannot be built
  - no `Basic` challenge (AC-21).
- Flask `/www` - a wrong passphrase is a 403, so the browser does not ask
  again - recorded by the walk (AC-20); the page text is changed only if
  the walk shows a dead end.

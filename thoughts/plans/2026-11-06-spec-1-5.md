## Overview

The sweep found 144 places where `docs/protocol/actingweb-spec.rst` (1.4) and
the library disagree. This plan settles every one: the specification is
rewritten where the library's behaviour is the working design, and the library
is fixed where its behaviour is a defect. The result is a version 1.5 the
library conforms to, and announces. It also makes outbound callbacks to
several subscribers concurrent and removes `FanOutManager`, which was never
connected to the publish path. Lands in 3.16 (minor, tag held), last of the
six plans of 2026-11-06: after `peer-authorisation-fixes`,
`subscription-wire-baseline`, `subs-list-cache-lifetime`, `attribute-list-v2-port` (whose wire behaviour it
documents) and `email-as-creator-at-write-time`.

Row identifiers (A1, P5, S8b, …) are the sweep's.

## Decisions Made

- **Full conformance.** Every row is settled on one side. The library is the
  working code and the specification a theoretical design, so the
  specification follows the library unless a deviation is a defect.
- **The specification is generic.** It describes the protocol, not the Python
  library. Nothing about the library's state, its extensions or what it does
  not implement goes into it. Library-specific surface (the `/items`
  endpoint, `?index=N`, the error bodies, the OAuth and MCP endpoints, the
  extra trust fields) stays in the library's documentation; where a peer
  could meet it, the specification says implementations MAY offer more.
- **Each deviation was classified** as a defect, a necessity or a matter of
  taste (sweep, "Proposed dispositions"). Defects are fixed in the library;
  the other two are specification edits.
- **Owner checks.** The library changes for: a non-JSON value labelled
  `text/plain` (P7); path-addressed list items as the specification describes
  them (P1 to P4); default deny when no permission pattern matches (T22). The
  specification changes for trustee access, which needs no trust relationship
  (T8). The extra `/meta` paths are defined in the specification (A8).
- **Two small library changes on silent rows:** an unknown granularity
  answers 400 (S19); `PUT /properties` answers 405 (P19). (A repeated trust
  request, T6, is the security plan's re-pair rule, landed with it: see
  below.)
- **Outbound delivery:** the sender posts to subscribers concurrently, with a
  bound, so a write waits for the slowest subscriber and not the sum.
  `FanOutManager` and its four inert settings are removed. The larger design
  (back-off, a per-peer breaker, a payload cap) becomes a todo.
- **The announced version** moves to `1.5` in the last phase, when the
  library conforms.
- **All specification text lives here**, including the four list-diff
  additions agreed for the `ListAttribute` plan.

Deduced; confirm at approval:

- **Optional mechanisms stay optional, in generic words.** Back-pressure, the
  circuit breaker, payload limits and compression are written so an
  implementation without them conforms: a sender that does not act on 429 or
  503 treats them as a failed delivery, and the stored diff with polling is
  the recovery every implementation has.
- **The overlap rule moves to the receiver** (C1): each subscription is
  delivered independently, and a subscriber holding overlapping subscriptions
  applies a change once.
- **Default deny is a breaking change for consumers** whose trust types
  define no property patterns: names no pattern covers stop being readable by
  a peer. The changelog gives the check.
- **`/meta/version` is the application's version**: a builder setting, with
  the library's version as the default when unset.

## What We're NOT Doing

- **Describing the Python library in the specification** - decided above.
- **Back-off, a circuit breaker, a payload cap with downgrade, compression** -
  a design of its own, filed as
  `thoughts/todo/outbound-callback-backpressure.md`; the specification keeps
  them as optional mechanisms.
- **MCP transport gaps** (O8: batches, SSE, `listChanged`, resource
  templates) - conformance to MCP revisions, not to this specification, and
  already in `thoughts/todo/mcp-batch-receive.md` and
  `mcp-oauth-connector-conformance-followups.md`.
- **`/sessions`, `onewaytrust`, `proxy`** - optional in the specification and
  not offered; `thoughts/todo/sessions-endpoint-and-advertised-options.md`
  keeps the first.
- **All-or-nothing `POST /properties`** (P8) - per-key acceptance with hooks
  is the working design; the specification is rewritten to it.
- **What the `ListAttribute` plan already does** - web-UI and REST list
  diffs (S3), filtering stored diffs (S8b), subtarget-level diffs on the
  receiver (S9), negative indices on the receiver (S23).
- **Requesting a resync when a diff cannot be applied, keying applied diffs**
  - `thoughts/todo/subscription-subscriber-fault-hardening.md`, minus the one
  item this plan takes from it (C7).

## Evaluation Notes

Two reviewers covered the five dimensions on 2026-11-06. **Their findings
are recorded here and not yet folded into the phases above. Four are
critical: the plan needs a second draft before approval.**

### Architecture

- **Critical: anonymous callers are authorised on the subscription and
  permission callback paths today.** The handler defers the check
  ("Allow unauthenticated requests to /callbacks/subscriptions and
  /callbacks/permissions, so do the auth check further below",
  `handlers/callbacks.py:183-184`), and the check that follows
  (`:197-202`, `:358-363`) is granted by the empty-role row
  `("", "callbacks", "", "a")` (`config.py:289`): for a caller with no peer id
  the `owner` row is skipped and the empty role matches (`auth.py:751-755`,
  `:800-803`). As traced, an unauthenticated POST to
  `/<actor>/callbacks/permissions/<peer>` reaches `store_permissions`
  (`handlers/callbacks.py:274`) and can run `_delete_revoked_peer_data`.
  **Traced from the code, not run; confirm with a request before it is filed
  as a security fix.** The generic path is the opposite (200, no hook).
  The rule the plan needs: 401 for an unauthenticated request everywhere
  under `/callbacks`, except a path an application opts in for anonymous POST
  (the demo documents such webhooks, `examples/demo/shared_hooks/app/callback_hooks.py:47`,
  `:106-107`, `:161`, and they cannot run today); and on the subscription and
  permission paths an authenticated peer whose id is the one in the path.
- **Critical: an empty-string diff is dropped at four points**, not one:
  `add_diff` (`subscription.py:155`), `callback_subscription`
  (`actor.py:2626`), the permission filter (`json.loads("")` raises and the
  handler fails closed, `actor.py:2900`, `:2941-2943`), and the receiver
  (`callback_data or {}`, `handlers/callbacks.py:649`). The `ListAttribute`
  plan moves the filter ahead of the store with "a diff filtered to nothing
  takes no sequence number", which would drop every delete. The stored and
  sent form should be the JSON-encoded `""`; a deleted list is `delete_all`.
- **Default deny: the site list is incomplete and the obvious fix breaks the
  root listing.** All built-in trust types define property patterns, so a
  non-matching name is already denied; `NOT_FOUND` arises only with no trust
  row, an unregistered type, no `properties` rules, or the empty target of a
  listing, which is kept on purpose (`permission_evaluator.py:727-734`). The
  other permissive sites are `handlers/properties.py:199-207`, `:1925-1929`,
  `:2109`, `interface/authenticated_views.py:99-103`, `:441`, `:654`,
  `interface/hooks.py:438`. The legacy `properties` rows are not dead
  afterwards.
- **409 on a repeated trust request half-deletes a re-initiated
  relationship**: the initiator overwrites its own row, gets 409, and deletes
  it (`actor.py:1703-1713`, `:1772-1774`), leaving the other side pointing at
  nothing. Create is a recorded deliberate upsert (`trust.py:450-452`). A peer
  that lost its secret cannot "delete first".
- **Path-addressed items change the permission target** (`notes/0` against
  `notes`), the hooks (the existing forms disagree with each other, and
  `/items` runs none) and the POST authorisation (legacy ACL against the
  evaluator). `items` and `metadata` keep their meaning only for the methods
  their routes declare.
- `register_diffs` cannot tell "subtarget not in this diff" from "resource
  gone" (`actor.py:3949-3965`), and only the handler holds the stored value
  for a deep path.
- The overlap rule is undefined when the more specific subscription has
  granularity `none`; it needs "only if that subscription delivers".
- An empty baseline and a failed fetch are the same `None`

### Security

- **Critical: the anonymous-callback trace was reached independently by the
  second reviewer, with one more consequence.** On the subscription callback
  path a low-granularity callback carries a `url` in its body, and the
  receiver fetches it with the peer's shared secret as the bearer
  (`handlers/callbacks.py:515`, `:617-623`). An anonymous caller who knows the
  actor id, a peer id and a subscription id can therefore have that trust's
  secret sent to a URL of its choosing, as well as inject diffs. On the
  permission path the peer id is enough to store chosen permissions, trigger
  deletion of replicated data when `auto_delete_on_revocation` is on (the
  consumer turns it on, `../actingweb_mcp/application.py:558-560`) and run
  the application's `permissions` hook. The fix: an authenticated bearer
  whose peer is the one in the path on both branches; the empty-role row
  narrowed or removed; a callback `url` fetched only when it starts with the
  peer's stored base URI. Still traced, not run.
- **Critical: default deny as drafted covers listings only.** A single-name
  GET, every PUT and every DELETE keep the fallback (`handlers/properties.py:199-207`,
  called at `:310`, `:781`, `:924`, `:1744`; copies at `:1925-1933`,
  `:2109-2117`; `interface/authenticated_views.py:99-103`;
  `interface/hooks.py:438-446`), and `POST /properties` never consults the
  evaluator (`:1073`, `:1716`). Hiding a name from the listing while a direct
  GET returns it is worse than either. The real reach of the fallback today
  is a trust row whose relationship is not a registered type: any name is
  accepted (sweep row T18), so a peer row named `creator` gets the legacy
  full grant. The empty target of a listing must stay `NOT_FOUND`, or every
  peer's `GET /properties` answers 403.
- Path-addressed items must be checked against the list name: with a pattern
  such as `shared/*`, `GET /properties/shared/0` would be allowed for a list
  the peer cannot read.
- Deletes sent as diffs pass through a filter that drops a bare `""` and
  passes any non-object value unchecked (`actor.py:2900-2906`,
  `:2941-2943`); a peer can subscribe to a subtarget it may not read
  (creation checks no pattern) and would receive its scalar values and its
  deletions. A non-object diff to a subtarget subscription has to be checked
  against the subtarget itself.
- Trustee access (T8): the bearer is the creator's own passphrase, the check
  is length only, `GET /<id>` returns it to creator, trustee and admin peers,
  and an admin peer can set the creator to `trustee`. So an admin peer can
  keep bearer access after its trust is deleted. The dropped MUST was the
  revocation path; the specification text has to state the conditions and
  that access ends only when the passphrase, creator or trustee root changes.
- 409 on a repeated trust request turns last-writer-wins into
  first-writer-wins on an unauthenticated endpoint: anyone can pre-register a
  pending row under a published peer id, and the real peer then gets 409.
- The concurrent sender with one pool per process is a cross-tenant
  amplifier: one actor whose subscribers hold connections open fills every
  slot. The bound has to be per write, with a deadline.
- Dropping the access check at subscription time (S8a) lets a subscriber with
  no read access observe write activity through sequence numbers.
